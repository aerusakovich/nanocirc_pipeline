## v1.0.0 - 2026-08-12

Initial release of nanocirc, created with the [nf-core](https://nf-co.re/) template.

### `Added`

- New optional quantification stage (`--run_quantify`): remap-based circRNA read counting. Without `--run_crossrun_merge`, each sample is quantified against its own discovery catalog. With it, every sample in a `group` shares one catalog built from that group's crossrun discovery output. New container `quay.io/anrusakovich/nanocirc-quant`.
- New confidence filter (`FILTER_CONFIDENT_DISCOVERY`, `bin/filter_confident_discovery.py`), applied after quantification. For `discovery`/`balanced_recall`, drops loci only CircNick-LRS called with weak read support. For `high_confidence`, drops IsoCirc-only calls with weak read support (guarding the `high_only_isocirc` exception that lets IsoCirc's own Low-confidence calls into that tier). New param `--circrna_confident_min_reads` (default `2`) sets the read-count cutoff. `balanced_precision` is untouched. Part of the new quantify.
- New DESeq2-ready count matrix (`BUILD_DESEQ2_MATRIX`, `bin/build_deseq2_matrix.py`), one per confidence tier, built when `--run_quantify true` is set: a wide isoform x sample count table plus `coldata`/`features` sidecar files, published under `circrna/deseq2/`.
- New `supporting_tools` column in clean TSVs (`bin/circrna_clean.py`, `bin/crossrun_annotate.py`): comma-joined names of every tool that called a locus (union across samples for cross-run merge). Needed by the new confidence filter above, and useful on its own for downstream filtering.
- Redesigned cross-run merge (`bin/smart_merge.py`'s `cross_run_hybrid_entries()`) to score each locus with two separate votes instead of one: a BSJ-position vote (decides which tier a locus qualifies for) and a structure vote restricted to the winning BSJ position (decides the final isoform structure). This stops a locus's correct BSJ call from being discarded just because a different run reported a slightly different exon structure at the same junction. Minority BSJ positions now keep their own separate isoform entry instead of being merged away. New param `--crossrun_min_tool_agreement` (default `2`) drops a single-run structure call unless that run's own tool agreement meets this bar; this cut cross-run false positives by about 34% in testing, for a small recall cost.
- Promoted the trusted_only-filtered merge output out of `--run_benchmark_modes` into the default pipeline as a permanent 4th confidence tier, `balanced_recall` (previously published only as `smart_consensus_filtered` in benchmark mode, and originally built on the plain `consensus` algorithm before the `consensus_hybrid` rewiring below).
- New `--isocirc_args`/`--circfl_args` params, letting users tune each tool's own detection settings on top of nanocirc's defaults. Scoped per tool by checking each container's actual `--help` output rather than assuming: `--isocirc_args` accepts any native isoCirc flag except `-t`/`--threads`/`--bedtools`/`--minimap2` (rejected at startup, nanocirc already manages these); `--circfl_args` only accepts `-u`/`-m <rmsk>` on circfull's `RG` step (also validated at startup) since every other circfull flag is a hardcoded I/O path nanocirc uses to chain `RG`/`DNSC`/`cRG`/`mRG` together, and overriding one would silently break that chain. No equivalent param for CIRI-long or circnick-lrs: both tools' native CLIs (verified directly, `CIRI-long call/collapse --help` and `long_read_circRNA run --help`) have no detection-tuning flags at all, only I/O paths nanocirc already sets. `circfl_seq.nf` previously declared an unused passthrough variable; now wired into `RG`.
- Wired up the previously-unreachable `high_only` filter mode (`bin/filter_confidence.py`) for the benchmark-mode `consensus_xstruct`/`priority` legacy merge algorithms (`CIRCRNA_FILTER_XSTRUCT_HIGH_ONLY`/`CIRCRNA_FILTER_PRIORITY_HIGH_ONLY`), so each now publishes all four documented filter variants (unfiltered, `no_low`, `trusted_only`, `high_only`) under `--run_benchmark_modes`, matching what the docs already claimed.

### `Changed`

- Renamed the `balanced` confidence tier to `balanced_precision` for clarity now that a recall-leaning counterpart (`balanced_recall`) exists alongside it (per-sample outputs, cross-run merge tiers, and docs updated accordingly).
- Updated `bin/smart_merge.py`'s `BSJ_PRIORITY`/`STRUCT_PRIORITY` tie-break orders to reflect updated benchmark results.
- Flattened merged output layout: `merged/smart/` and `merged/pairs/` no longer exist as separate subdirectories. Smart-merge/filter/annotate/finalize outputs publish directly under `merged/` (legacy `strict`/`relaxed`/`exon_based` benchmark-mode subdirectories are unchanged); pairwise bedtools comparison files are no longer published.
- `--wet_lab isocirc` now defaults `--run_cirilong` to `false`. On real isoCirc-protocol data, CIRI-long has hung for 24+ days without finishing; benchmarking shows leaving it off costs about 0.01 F1 at the `discovery`/`balanced_recall`/`balanced_precision` tiers and improves `high_confidence`. `--run_cirilong true` opts back in.

### `Fixed`

- `QUANT_GENOME_INDEX` bumped from `process_low` (12GB) to `process_high` (72GB, `* task.attempt`) with explicit retry, confirmed by a real SIGKILL (OOM) failure building a minimap2 splice index for a full mouse genome.
- Boolean CLI flags (`--run_isocirc`, `--run_circfl`, `--run_cirilong`, `--run_circnick`, `--run_crossrun_merge`, `--run_quantify`, `--run_benchmark_modes`, `--skip_qc`, `--skip_fastqc`, `--skip_nanoplot`, `--skip_multiqc`, `--skip_annotation`) passed with an explicit `false` (e.g. `--run_circnick false`) had no effect: `NXF_SYNTAX_PARSER=v2` delivers CLI params as strings, and a non-empty string is truthy in Groovy, so every `if (params.run_x)` gate ran regardless of what was passed. A previous fix attempt (`params.x = params.x.toBoolean()` in `main.nf`) did not work either, confirmed with a minimal repro: Nextflow keeps returning the original CLI string on every later read of `params.x`, ignoring the reassignment. Found via a smoke test that toggled tools off one at a time: disabling `circnick` still ran `CIRCNICK_LRS`, and toggling off `run_crossrun_merge` still ran `CIRCRNA_CROSSRUN_MERGE`, which then crashed on a single-sample group (`add_isoform_confidence.py --pairs` needs at least 2). Fixed by reading each flag once into a local boolean (`asBool()` in `workflows/nanocirc.nf` and `subworkflows/local/circrna_analysis.nf`, inlined in `conf/modules.config`) instead of relying on `params.x`'s truthiness directly.
- `CIRCRNA_FINALIZE` crashed with an "input file name collision" whenever exactly 2 of the 4 detection tools were inactive at once: their expression-file placeholders (`ch_iso_expr`/`ch_fl_expr`/`ch_nick_expr`/`ch_ciri_expr` in `subworkflows/local/circrna_analysis.nf`) all used the same literal filename `NO_FILE`, and Nextflow can't stage two different missing-input placeholders under an identical name in the same task. Only surfaced once the boolean-flag fix above made turning tools off actually work. Gave each tool its own placeholder name (`NO_FILE_ISOCIRC`/`NO_FILE_CIRCFL`/`NO_FILE_CIRCNICK`/`NO_FILE_CIRILONG`, matching the convention already used elsewhere in the same file and in `quant_coverage_flag.nf`), and updated `modules/local/circrna_finalize.nf`'s presence checks to match.
- `bin/add_isoform_confidence.py`'s `count_to_score()` originally binned tool-agreement counts as a raw percentage of active tools (`count/n_active`), which only matched the intended Low/Medium/High cutoffs when all 4 tools are active. With fewer tools running, a single supporting tool crossed past the Low cutoff (e.g. 1/3 = 33%, above the 25% bound), promoting single-tool calls into `Medium`. This broke `balanced_precision`'s `no_low` filter whenever a tool was disabled: on isoCirc-protocol data with `--run_cirilong false`, it grew from a normal ~1,100 loci/run to over 7,000 with worse precision than `discovery`. Replaced with a fixed scale, independent of `n_active`: 1 supporting tool is always Low, 2 is always Medium, 3+ is always High. A given score now means the same amount of evidence in every run. Note this also changes results in the normal 4-tools-active case versus the original design (3-of-4 agreement is now High, previously Medium). One consequence: single-tool runs (`--wet_lab circnick`) can never exceed 1 supporting tool, so `balanced_recall`/`balanced_precision`/`high_confidence` are always empty there by design (no cross-tool consensus is possible with one tool); only `discovery`, optionally narrowed by `filter_confident_discovery.py`'s read-count filter (`--run_quantify`), gives single-tool runs a meaningful filtered output.
- `bin/crossrun_annotate.py` stripped the `|iso1`/`|iso2` isoform suffix from `bsj_id` before using it as the key for both `filtered_ids` (which bed12 rows survive the tier's `min_count` filter) and `classify_types()`'s per-locus type lookup. Since a locus can have several isoform records with independently-labelled structures, this meant: (1) a bed12 row could survive filtering just because a *different* isoform at the same BSJ position passed `min_count`, even though its own row never made it into `_clean.tsv` (confirmed on `final_benchmark` human_run1's `balanced_precision`: 2,063 bed12 rows vs 2,051 TSV rows, 146 bed12-only + 134 TSV-only); (2) multiple isoforms at one locus collapsed into a single, only-sometimes-correct type classification (e.g. `eciRNA` vs `EIciRNA`), since `bedtools intersect` results for same-named rows got summed together and `spliced_length` was silently overwritten by whichever isoform was processed last. Fixed both to key on the full isoform-specific `bsj_id`. The one place still correctly using the stripped, locus-only id is the per-sample `lookup()` call (checking whether each contributing run's own tier output supports this BSJ position) — isoform labels aren't stable across separate runs (`iso1` in one run has no relationship to `iso1` in another, see `smart_merge.py`'s own docs), so that comparison has to stay locus-level; only comparing a script's own bed12 output against its own TSV output (both produced by the same preceding `smart_merge.py` call) is safe to do at full isoform granularity.
- `bin/smart_merge.py`'s `consensus_hybrid` mode (the source of `discovery`, and, after tier filtering, `balanced_precision`/`high_confidence`) collapsed every tool down to `best_record()` — its single highest-scoring call at a locus — before any cross-tool vote ran. A tool that itself correctly resolved 2+ real isoforms at one BSJ (different reads supporting different structures) only ever contributed one of them; the rest were discarded before the vote ever saw them. Confirmed on `final_benchmark`: at multi-isoform GT loci a tool fully resolved on its own, NanoCirc's tiers failed to fully resolve the same locus 45% of the time on human and 77% on mouse, and 91-100% of those losses traced directly to a tool having 2+ raw calls at that exact locus. Fixed by keeping every distinct isoform call from `isocirc`/`circfl`/`cirilong` at the winning BSJ (not just the best one), while `circnick` still collapses to its single best call, since its own isoform-level calls are unreliable (near-zero true-isoform recovery even under a loose reciprocal-overlap threshold). Raised fully-resolved multi-isoform families from 15 to 76 out of 655 run x family instances (human+mouse, 5.1x), with zero change to the missed count. Confirmed the recovered entries survive both `filter_confident_discovery.py` and `filter_confidence.py`'s `trusted_only` mode unconditionally (never `circnick`-only by construction, and their single-tool source is always in `trusted_only`'s default trusted-tool set); `isocirc_only` mode (`balanced_precision`) keeps only the IsoCirc-sourced recoveries, correctly, by the same narrow-trust design it already applies to any other tool's Low-confidence calls.
- `balanced_recall` never benefited from the `consensus_hybrid` isoform-recovery fix above, since it turned out to source from a different merge mode: `subworkflows/local/circrna_analysis.nf`'s `CIRCRNA_FILTER_CONSENSUS_TRUSTED` read `CIRCRNA_SMART_MERGE.out.consensus_bed` (plain `consensus` mode, its own separate `best_record()`-collapsing vote, matching `balanced_precision`/`high_confidence`'s `discovery`-derived design.). Confirmed by tracing one real family through the actual Nextflow work directories: `CIRCRNA_FILTER_CONSENSUS_TRUSTED`'s own raw output never had the recovered isoform, because its input (`smart_consensus.bed12`) never had it either. Rewired `CIRCRNA_FILTER_CONSENSUS_TRUSTED` to read `hybrid_bed`/`hybrid_conf` instead, matching `balanced_precision`/`high_confidence`. `filter_confidence.py`'s `trusted_only` mode needed no change (already tool-source-based, not mode-based). Checked whether `bin/smart_merge.py`'s crossrun mode (`cross_run_hybrid_entries()`, used by `CIRCRNA_CROSSRUN_MERGE` for every crossrun-merged dataset) would still block the recovered isoforms via its own `--min_corroboration` (default 2) weak-single-run-evidence filter: on `final_benchmark` mouse, every one of the 17 families where `discovery` reached full resolution but `balanced_recall` didn't already had both isoforms independently and consistently present across all 3 runs, so they clear the existing corroboration bar without needing any change to crossrun's own logic. `cross_run_hybrid_entries()` itself was left untouched.
- `bin/smart_merge.py` computed all 4 merge modes (`consensus`, `consensus_xstruct`, `consensus_hybrid`, `priority`) on every run, even though `consensus`/`consensus_xstruct`/`priority` are only ever read under `--run_benchmark_modes`, and never at all in cross-run mode (`CIRCRNA_CROSSRUN_MERGE` only reads the hybrid output). Added `--benchmark_modes` (new flag, off by default) to gate the three legacy modes' voting logic; `consensus_hybrid` is unaffected either way (verified byte-identical output with the flag on vs off). `modules/local/circrna_smart_merge.nf` now only passes the flag through when `params.run_benchmark_modes` is set. Also wired the previously-unreachable `high_only` filter mode (`bin/filter_confidence.py`) onto `consensus_xstruct`/`priority`'s benchmark-mode diagnostics (`CIRCRNA_FILTER_XSTRUCT_HIGH_ONLY`/`CIRCRNA_FILTER_PRIORITY_HIGH_ONLY`), completing the 4 filter variants the docs already claimed each published.
